# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

OpenBomber is a Bomberman-style 2D game in C++17 with OpenGL 3.3 core (GLFW + GLAD + GLM, stb_image for textures), written for a university course on graphics processing fundamentals. Commit messages are written in Portuguese.

Current state: a 30×10 tile map and one player are drawn with textured sprites. The player moves one tile at a time (WASD/arrows, with a cooldown) and faces the direction of movement; Space places a bomb on the player's tile; Esc or closing the window quits. Bombs never explode yet: `Bomb` and `Fire` exist only as headers (`src/game/bomb.h`, `src/game/fire.h`), with no `.cpp` and no use in `Game`. The map starts all `EMPTY`, so there are no walls in play.

## Build & run

Nix (preferred on Linux; a local, gitignored `.envrc` with `use flake` lets direnv load the dev shell automatically):

```sh
nix build            # builds ./result/bin/openbomber
nix run              # build and run
nix develop          # dev shell with cmake, clangd, glfw, glm, libGL, and stb on CPATH
```

Plain CMake (inside the dev shell or with deps installed):

```sh
cmake -B build
cmake --build build
./build/openbomber
```

- Run the binary from the repository root: sprites are loaded from relative paths like `assets/player.png`, and the Nix package installs only the binary, not `assets/`.
- Outside Nix, CMake falls back to `FetchContent` to download GLFW 3.4 and GLM 1.0.1. The Nix build disables network fetching and forces `find_package`.
- `stb` (nothings/stb) is supplied only by the flake via `CPATH`; CMake does not know about it. A non-Nix build needs `stb_image.h` on the include path some other way.
- `.devcontainer/` provides a Debian container with Nix (flakes enabled) that pre-builds the dev shell.
- `setPath.bat` is a Windows helper that adds MSYS2 UCRT64 and CMake to `PATH` for building on Windows.

clangd reads `build/compile_commands.json` (generated by `cmake -B build`) and must run inside the dev shell to find Nix-provided headers like GLM and stb.

There are no tests or linters configured.

## Architecture

Ports and adapters:

- `src/game/` is the domain and must not include GLFW/GL (GLM is fine). It defines the ports `Renderer` (`draw(const Game &)`) and `Controller` (`update`, `isDown`, `isPressed` over `ControllerAction`), plus `Game`, `Map`/`MapTile`, and `Player`.
- `Game::run` is the loop: compute `dt` with `steady_clock`, tick player cooldowns, `controller.update()`, handle movement and bomb placement, `renderer.draw(*this)`. There is no frame cap; pacing comes from vsync (`glfwSwapInterval(1)`).
- Game state lives on the tile grid. `MapTileType` covers `EMPTY`, walls, `BOMB`, `FIRE` and `HAS_PLAYER`; a player can only step onto an `EMPTY` tile, marks the tile it enters as `HAS_PLAYER`, and clears it back to `EMPTY` on leaving (a `BOMB` left behind stays). Positions are `glm::vec2` in tile units, with y growing downward.
- `src/infra/opengl/` holds the adapters. `GlfwPlatform` owns GLFW, the window and the GL context, creates `GlController` and `GlRenderer` after them and destroys them before (explicitly, via `unique_ptr::reset`). Headers only forward-declare `struct GLFWwindow`.
- `GlController` maps keys to actions in a static `KEY_BINDINGS` table, polls events in `update()`, and keeps current/previous maps so `isPressed` is an edge trigger.
- `GlRenderer` uses one shader program and one unit quad (VAO/VBO, `GL_TRIANGLE_FAN`). The orthographic projection is hardcoded to 30×10 world units (it does not read the map size), and each sprite is placed with a `model` translate. The vertex shader takes `frameOffset`/`frameSize` uniforms in UV space to cut a frame out of a sprite sheet: tiles use the whole texture; `player.png` is a 2×4 sheet whose row is picked by `Direction`. Alpha blending is on and textures use `GL_NEAREST`.
- `Sprite` holds the image path, size and GL texture id; `GlRenderer` keeps one `Sprite` per `MapTileType` plus the player sprite, loads them in its constructor and deletes the textures in its destructor.
- `main.cpp` is the composition root: builds the platform (800×600 window), injects its controller/renderer into `Game`, and turns exceptions into an error message and exit code 1.

## Conventions

- Every class has a `.h`/`.cpp` split. `CMakeLists.txt` globs `src/*.cpp` recursively (with `CONFIGURE_DEPENDS`), so new `.cpp` files are compiled automatically.
- Include roots are `src/`, `include/`, and `include/glad/`, so includes are written relative to `src/` (e.g. `#include "game/map.h"`).
- File names are kebab-case (`gl-renderer.cpp`), classes PascalCase, enum values UPPER_SNAKE_CASE. Gl adapters are prefixed `Gl`/`Glfw`.
- Free helper functions in a `.cpp` are forward-declared just above the method that uses them and defined after it.
- GLAD is vendored: `common/glad.c` plus headers in `include/glad/`. `<glad/glad.h>` must be included before `<GLFW/glfw3.h>`; they are separated by a blank line so clang-format doesn't reorder them.
- `STB_IMAGE_IMPLEMENTATION` is defined once, in `gl-renderer.cpp`.
- Art lives in `assets/` as `.aseprite` sources next to exported 32×32 `.png` files (`background.png` is not used yet).
